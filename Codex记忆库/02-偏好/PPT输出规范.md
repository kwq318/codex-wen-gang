# PPT 输出规范

## 一、核心原则

1. **每页一个论点，标题即结论** — 听众扫标题就知道这页在说什么
2. **用「痛点→方案→代价」三段结构** 写正文，不要罗列功能
3. **决策层看大字数据，技术层看架构逻辑** — 同一份内容分层展示
4. **技术细节归附录**，不占用主线页面
5. **每页底部加行动项或决策点**，不开放式结尾

---

## 二、听众分类与对应风格

| 听众 | 页数 | 信息密度 | 语言风格 | 核心叙事 |
|------|------|----------|----------|----------|
| 决策层（总监/VP/总工） | 6-10 页 | 稀疏 — 大字数据 + 一句话结论 | 战略语言，不谈技术细节 | 行业趋势 → 不上方案的代价 → 方案价值 → 合作路径 |
| 技术层（座舱团队/研发） | 10-15 页 | 密集 — 架构图 + 技术参数 | 专业术语，但场景驱动 | 现有架构分析 → Agent 平台集成方式 → 接口定义 → 落地节奏 |
| 采购层 | 8-12 页 | 中等 — 资质 + 案例 + 商务模型 | 商务语言，证据导向 | 公司实力 → 案例佐证 → 商务模型 → 实施计划 |
| 混合（三方联合会议） | 8-10 页 | 中等 — 每页兼顾两方关注点 | 高层定调，硬数据支撑 | 先共识痛点 → 再展示方案 → 最后谈落地 |

---

## 三、每页结构标准

```
┌──────────────────────────────────────┐
│ 标题栏: [动词短语] 一级结论          │  ← 标题即结论
├──────────────────────────────────────┤
│                                      │
│ ▸ 痛点/现状（一句话）                │  ← 先引起共鸣
│                                      │
│ ▸ DDD （大字数据/核心图）            │  ← 视觉锚点
│                                      │
│ ▸ 方案对应（2-3个要点）              │  ← 如何解决
│                                      │
│ ▸ 不上方案的代价 / 差异化价值        │  ← 促进行动
│                                      │
├──────────────────────────────────────┤
│ 底部: ▶ 下一步行动 / 决策点          │  ← 不开放式结尾
└──────────────────────────────────────┘
```

**数据展示规则**：
- 关键数字独立成行，字号突出（如 `60万辆` `-30% TCO` `8-12周`）
- 对比类数据用表格，不使用段落文字
- 架构图/流程图优先于文字描述

## 四、场景化 PPT 模板

### 场景 A：首次客户拜访 / 破冰

| 页码 | 标题（即结论） | 内容要点 |
|------|---------------|----------|
| 1 | 封面 | 客户Logo + 方案名 + 日期 |
| 2 | 行业正在经历座舱智能化的三个转折点 | 趋势数据：出口合规压力、AI 体验分化、开发效率瓶颈 |
| 3 | 不上智能化的代价正在扩大 | 「错过窗口期」的隐性成本：上市延迟、竞品碾压、合规罚款 |
| 4 | 我们帮先行者解决了同样的问题 | 1 个同行标杆案例 + 关键数据（接入周期、人力节省） |
| 5 | 下一步：确认我们是否对上了需求 | 开放收尾，约定第二次技术交流 |

### 场景 B：技术交流 / 方案演示

| 页码 | 标题（即结论） | 内容要点 |
|------|---------------|----------|
| 1 | 封面 | 客户Logo + 方案名 + 日期 |
| 2 | 现有座舱方案面临三个共性挑战 | 用客户的产品语言描述痛点（不用销售语言） |
| 3 | Agent 平台不做替代，只做增强 | 架构图：不替换现有 OS，仅新增体验层 |
| 4 | 接入周期 8-12 周，不改底层 | 集成方式 + 接口清单 |
| 5 | 已量产案例验证 | 同行业技术验证数据 |
| 6+ | 附录：技术参数与部署环境要求 | 归入附录页 |

### 场景 C：RFQ / 竞标

| 页码 | 标题（即结论） | 内容要点 |
|------|---------------|----------|
| 1 | 封面 | 方案名 + 投标编号 + 日期 |
| 2 | 核心能力一页速览 | 表格：需求 ←→ 对应能力 ←→ 交付证明 |
| 3-4 | 方案如何满足[核心需求] | 每页绑定一个客户 RFQ 中的核心需求 |
| 5 | TCO 对比：我们 vs 竞品 | 隐性成本 + 集成周期 + 维护升级成本 |
| 6 | 交付团队与执行计划 | Timeline + Milestone |
| 7 | 为什么选择我们 | 3 个不可替代性，不是功能列表 |

### 场景 D：决策层战略汇报

| 页码 | 标题（即结论） | 内容要点 |
|------|---------------|----------|
| 1 | 封面 | 汇报主题 + 日期 |
| 2 | 行业正在发生变化（3个关键趋势） | 大字数据 + 一句结论 |
| 3 | 我们面临的机遇 | 市场规模 + 客户需求明确性 |
| 4 | 为什么现在必须行动 | 窗口期 + 不上方案的代价（量化） |
| 5 | 合作路径和里程碑 | 路线图 + 关键决策点 |

## 五、输出格式（Markdown → PPT 转换指南）

我输出的内容采用结构化 Markdown，你按以下规则转成 PPT：

```
## 每页标题（即结论）     ← 贴进 PPT 标题栏

> 痛点/现状一句话         ← 贴在正文区顶部，加引号或色块

**60万辆**              ← 大字数据，独立文本框，加粗放中间

- 要点 1                 ← 正文列表
- 要点 2
- 要点 3

▶ 下一步：约定技术交流时间  ← 底部行动项文本框
```

**架构图/流程图**：我用 Mermaid 代码块生成，你截图插入或转成 Excalidraw 导出 PNG 嵌入。
