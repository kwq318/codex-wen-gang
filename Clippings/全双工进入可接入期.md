§ Ⅰ

## 重要新闻动态

01已落地

### Google 将实时语音推向 Agent API

Gemini 3.8 Live 支持异步函数调用、后台推理、多语言和 Live API 接入，并公布了按音频分钟计费的价格。

产品关系

适合构建“前台持续说话、后台执行导航/充电/预约”的车载任务流。 <sup><a href="#ref-1">1</a></sup>

02已落地

### 阶跃发布 StepAudio 3 Realtime

StepAudio 3 Realtime 强调全双工、自然打断、情绪理解、边说边思考与工具调用，并上线开放平台。

产品关系

可作为中文与国内车型的 S2S 候选，应用层仍需承担车控权限、长任务和合规。 <sup><a href="#ref-3">3</a></sup> <sup><a href="#ref-4">4</a></sup>

03已落地

### 阿里百炼新增 AOQ 弱网接入路径

Realtime API 提供 AOQ、WebRTC、WebSocket 三种协议，AOQ 面向弱网、多模态和低延迟场景，并支持实时语音模型。

产品关系

车载实时语音的选型将同时包含模型、传输协议、回声消除与端侧平台。 <sup><a href="#ref-5">5</a></sup>

§ ⅡExperience

## Agentic 语音体验趋势

### 从“等模型答完”转向“先维持语音流”

普通任务使用低延迟语音模型，复杂任务在后台推理；车载助手应拆分立即反馈、后台执行和结果回传三层。 <sup><a href="#ref-1">1</a></sup> <sup><a href="#ref-3">3</a></sup>

### 全双工成为新的体验基线

差异不再是“能不能打断”，而是能否区分咳嗽、噪声、临时插话、任务修改与任务取消。 <sup><a href="#ref-1">1</a></sup> <sup><a href="#ref-3">3</a></sup>

### 工具调用必须脱离实时语音主链路

车载 Agent 应以任务对象管理导航、充电、餐厅、预约和支付权限，而不是把复杂请求拆成多个轮次。 <sup><a href="#ref-1">1</a></sup> <sup><a href="#ref-5">5</a></sup>

§ ⅢPlatforms

## 大模型厂商 S2S 规划

### Gemini 3.8 Live / Extended Thinking

支持 Live API、异步函数调用、交错推理和多语言；音频输入 0.005 美元/分钟、输出 0.018 美元/分钟。车载可用性高，适合作为海外云端候选。 <sup><a href="#ref-1">1</a></sup> <sup><a href="#ref-2">2</a></sup>

### StepAudio 3 Realtime

覆盖全双工、打断、情绪、副语言、边说边思考和工具调用；已上线开放平台，但完整价格、海外区域、SLA 和车规条款证据不足。 <sup><a href="#ref-3">3</a></sup> <sup><a href="#ref-4">4</a></sup>

### Qwen Realtime / 百炼 Realtime API

提供实时全模态、实时语音对话及 AOQ、WebRTC、WebSocket 三类协议；价格和并发限制需在控制台确认，适合纳入弱网传输层评估。 <sup><a href="#ref-5">5</a></sup>

§ ⅤNew Products

## 创新型语音产品洞察

### 把“真实问题用户”变成语音 Agent 的测试对象

**核心 idea：** 用 persona、scenario、噪声、口音、打断和网络条件模拟非理想用户。  
**过去没解决的事：** 固定脚本无法覆盖用户反悔、情绪升级和音频异常。  
**技术栈：** 真实音频/电话路径、30+ 音频评分器、100+ 转写评分器和 API/CI 测试。  
**搬到车上：** 成立，可扩展为司机、乘员、音乐、路噪和断网组合测试。  
**可借鉴范式：** 把首响、误打断、任务丢失和车控误执行纳入每次发布回归。 <sup><a href="#ref-7">7</a></sup>

§ ⅥImplications

## 对产品的启发

a

### 产品体验设计输入

把持续对话作为主循环；打断必须与任务状态绑定；主动服务只允许在可解释、可延后、可关闭的触发器内发生。 <sup><a href="#ref-1">1</a></sup> <sup><a href="#ref-3">3</a></sup>

b

### 路线与合作选型

Gemini 适合海外云端候选，StepAudio 适合中文与国内场景，阿里 AOQ 适合弱网传输评估；选型指标必须包含任务闭环质量。 <sup><a href="#ref-1">1</a></sup> <sup><a href="#ref-3">3</a></sup> <sup><a href="#ref-5">5</a></sup>

c

### 给车厂提建议

优先建设多区拾音、回声消除、可取消的异步工具接口和本地安全壳；断网时保留低风险车控、紧急呼叫与基础导航缓存。

d

### 行业认知与新机会

汽车 Agent 的商业价值可能先从售后、服务预约和经销商运营出现；语音 Agent 评测也正在成为独立产品层。 <sup><a href="#ref-6">6</a></sup> <sup><a href="#ref-7">7</a></sup>

§ ⅦExperiments

## 可以做的尝试

Prototype 01

### 前台连续、后台执行的复合任务

使用 Gemini 或 StepAudio 实现“沿途快充 + 餐厅预约 + 导航”，验证后台执行期间的自然应答、改目的地和失败恢复。

指标：首响、任务恢复率、工具失败后的可解释性。

Prototype 02

### 建立车载 Voice Agent Stress Test

参考 NovaSynth 的 persona/scenario，加入司机、乘员、路噪、音乐、方言、中英混说和断网变量。

指标：误打断、任务丢失、车控误触发、恢复时间。

Prototype 03

### AOQ、WebRTC、WebSocket 车内网络对照

在相同模型和音频输入下比较三类协议的建连、弱网连续性、回声消除与资源开销。

指标：P50/P95 首响、重连时间、CPU/内存占用。 <sup><a href="#ref-5">5</a></sup>
