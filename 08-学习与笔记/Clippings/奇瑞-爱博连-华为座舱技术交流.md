以下是基于本次奇瑞 - 爱博连 - 华为座舱技术交流会议整理的完整会议纪要： **奇瑞 - 爱博连 - 华为座舱技术交流会议纪要** **一、会议基本信息**

1. 会议时间：2026 年 8 月（周五下午 4 点）
2. 参会人员：
	- 华为侧：销售董首剑、解决方案售前李慧、线上研发团队、CTO 黄昕
		- 艾博连侧：李彬、康维庆、产品总监于雯、程坤
3. 会议背景：本次会议是上一次座舱技术交流的延续，艾博连与华为为长期合作关系，此前已在北汽、长城、东风等多个车企项目中开展合作，本次重点围绕 **8397 平台座舱智能体方案** 展开深度交流
	\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
	。

**二、核心技术架构介绍** 本次方案采用云端 + 端侧融合的整体架构，核心内容如下：

1. 云端 master agent 体系
	- 车端原有 ASR 输出的原始文本会双发，一路给到车端原有语音模型做 NLU，另一路通过华为侧 voice kit 传输到云端 master agent
		\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
		。
		- master agent 依托 LLM 大模型能力，完成意图分类、垂类场景落域、意图二次识别，通过内置仲裁规则输出最终意图，底层依托长短期记忆模块、知识库、agent 注册管理模块提供支撑
		\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
		。
		- 已规划的垂域 agent 包含周边推荐 agent、安全用车 agent、出行 agent、娱乐 agent，后续还会持续扩展更多智能体能力
		\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
		。
		- 配套提供 agent studio 平台，可实现智能体业务流程设计、注册管理、版本跟踪、功能评测、运营日志全生命周期管理，支持 API、function、MCP 等多种方式接入新能力
		\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
		。
		- 内置任务编排 runtime 机制，支持多 agent 之间并行 / 串行执行调度、A2A 通讯、状态流转管理
		\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
		。
2. 端侧融合机制
	- 车端原有传统语音引擎输出的 NLU 结果，会和云端 master agent 返回的结果一同提交给端侧 voice kit 做本地仲裁，最终裁定采用哪一路结果，既保留车厂原有 NLU 的垂域优势，又能发挥云端大模型的泛化能力
		\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
		。
		- 端侧新增 VLM 多模态大模型，用于获取 OMS、DMS 数据，完成视觉理解推理，生成结果后直接供给端侧 master agent 处理，无需和云端交互，可直接触发舱内舱外 agent、哨兵 agent 等执行对应动作
		\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
		。
		- 端侧可视为独立的 MCP / 子 agent，通过 MCP 协议或 A2A 协议被云端主控大脑调用，支持云端通过 TSP 平台下发指令触发端侧执行
		\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
		。

**三、海外生态 agent 商用规划**

1. 音乐类 agent（含海外主流音乐应用、电台、有声书）： **2027 年 Q1 满足商用** ，已完成可演示 demo，支持语音直接调用相关能力
	\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
	。
2. 视频 + 本地生活类 agent（含长中短视频、Uber、餐饮等服务）： **2027 年 Q2 满足商用** ，目前正在推进深度信源对接开发
	\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
	。
3. 相关说明：所有 agent 均已完成主流海外信源的前期对接，当前正在做语音深度融合的定制化开发，后续可通过开放 API 接口快速接入新的生态应用
	\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
	。

**四、端侧多模态方案细节** 本次端侧多模态能力与 **面壁智能** 合作开发，适配 8397 平台的模型配置如下：

1. 3B 参数 VRM 模型：用于舱内外主动车控，支持舱外天气识别、下车 / 起步提醒，舱内上车仪式识别、宠物（仅支持猫和狗）检测、儿童关怀等场景，相关能力已在测试车辆上完成 demo 验证
	\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
	。
2. 1.2B 参数 VRM 模型：用于离车哨兵模式，支持各类异常行为标签识别，相关能力已完成实测验证
	\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
	。
3. 0.9B 参数模型：支持离线语音意图识别
	\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
	。
4. 性能优化说明：所有视觉识别场景均采用事件触发机制，无需全程高负载运行，避免算力占用过高的问题，同时可支持多内容同步识别，不同场景的触发条件独立配置
	\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
	。

**五、关键问题对齐与共识**

1. 算力适配要求：方案移植到 8255 平台时，新增 CPU 算力占用需控制在 **15 核以内** ，若主机预留算力不足，可将部分模块放到 AI Box 上做动态调节，保证方案可落地到更多车型
	\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
	。
2. 降级策略：网络通畅时优先采用云端方案，网络中断时自动切换为本地方案；大模型响应超时阈值设置为 **2 秒** ，超时后自动触发本地降级，同时云端与端侧的语音合成音色尽量保持一致，避免用户体验割裂
	\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
	。
3. 出海合规要求：欧盟区域禁止使用童音作为语音助手音色，可替换为普通女性 / 男性音色规避合规风险；方案整体架构支持多区域适配，不同地区可灵活替换合规的模型组件，云端架构尽量保持统一，降低维护成本
	\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
	。
4. 多语言支持：系统可同时支持 **3-5 种语言** ，后续可扩展支持数十种语种，支持实时语种自动切换，适配不同国家用户的使用习惯
	\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
	。
5. 合作模式：三方合作可根据项目实际情况确定主导方，灵活选择签约主体，当前已在北汽、长城等多个项目中验证过该合作模式的顺畅性
	\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
	。

**六、后续项目推进计划**

1. 项目定点时间预计为 **2026 年 8 月** ，后续启动正式开发，首版车型 SOP 时间为 2027 年 1 月

3. 各方同步推进 demo 版本开发，验证三方联合方案的落地能力
	\- [1](https://meetings.feishu.cn/minutes/obcnakghs9j4sb59wgwktoog?psg_id=7671194497665321934&refer_index=1&refer_type=citation)
