# 销售研究

## 目标

将分散的公开信息转化为销售团队可直接使用的账户情报：明确公司是否值得投入、谁可能参与决策、为什么现在值得联系、应当围绕什么业务问题展开对话，以及下一步如何验证假设。

默认遵循“事实—推断—行动”三层结构：

- **事实**：来源明确、可复核的公开信息。
- **推断**：基于事实得出的销售相关判断，明确标注为推断，不冒充事实。
- **行动**：建议联系谁、先问什么、引用什么证据、如何安排下一步。

## 研究边界与证据规则

1. 优先使用一手来源：公司官网、新闻稿、监管文件、招聘页面、产品文档、官方博客、官方社交账号和本人公开资料。
2. 使用搜索或浏览获取实时信息。对融资、并购、领导层、招聘、产品和技术栈等易变信息注明具体日期。
3. 每个重要结论都附来源名称、页面标题、发布日期或访问日期；无法核验的内容写“未确认”。
4. 区分“没有找到证据”和“事情不存在”。避免把搜索缺失写成否定结论。
5. 不编造邮箱、电话、任职关系、预算、收入、员工数量、客户名单或个人经历；不要绕过登录、付费墙、验证码或隐私限制。
6. 只整理与职业和业务相关的公开信息。忽略敏感个人信息、家庭情况、健康、政治观点、宗教、种族等与销售无关内容。
7. 对联系人优先使用其所在公司官网、演讲资料、署名文章、公开职业档案和会议页面；谨慎处理同名匹配。
8. 如果来源之间冲突，列出冲突并说明采用哪一来源及理由。

## 工作流

### 第一步：明确研究问题

先确认或从请求中提取：

- 目标公司、域名、所在地区和研究范围；
- 目标产品或服务，以及理想客户画像；
- 目标联系人或目标职位；
- 研究目的：账户排序、首次触达、会议准备、机会推进或竞争分析；
- 时间范围，例如最近十二个月；
- 需要的交付形式：简报、表格、外联角度、问题清单或行动计划。

缺少信息时，采用最小合理假设并明确写出；只有会显著改变结论时才追问。

### 第二步：研究公司

按下列顺序收集并交叉验证：

1. **基本画像**：主营业务、客户对象、行业、成立时间、总部和关键地点、规模或阶段。
2. **业务与产品**：核心产品、主要用例、定价或商业模式、服务地区、合作伙伴和竞争替代品。
3. **近期动态**：最近十二个月的融资、并购、领导层变化、产品发布、扩张、裁员、重大客户、监管或诉讼事件；每条标注日期。
4. **增长与组织信号**：职位数量、相关团队招聘、职位要求中的新工具或新流程、地区扩张、组织重组。
5. **技术栈与集成**：仅记录有证据的技术；将官网技术页、招聘信息、开发者文档、公开代码和技术检测结果分级，避免把推测当事实。
6. **业务痛点线索**：招聘职责、客户评价、领导层公开发言、产品变更、服务状态或新闻中体现的效率、规模化、合规、安全、数据或收入问题。

### 第三步：研究联系人

围绕影响力和切入点整理：

- 当前职位、部门、任职时间和职责范围；
- 可核验的职业经历、教育或专业资格；
- 可能的预算、项目、流程或技术影响力；
- 向谁汇报、谁可能是执行者、使用者、财务或安全评审者；
- 最近公开发言、文章、演讲、产品观点或公司项目；
- 与目标方案最相关的工作主题，以及适合验证的开放式问题。

不要仅因职位名称就断言其为最终决策人。使用“可能影响者”“待确认的经济买方”或“执行负责人”等谨慎表述。

### 第四步：识别并分级购买信号

从 `references/signal-indicators.md` 选择信号，并给出：信号、证据、日期、新鲜度、强度、与方案的关联、建议动作。

- **强信号**：明确项目、预算、相关招聘、采购或实施需求、领导层公开承诺、近期产品或组织变化。
- **中信号**：扩张、重复招聘、流程变化、技术迁移迹象、客户痛点或相关内容互动。
- **弱信号**：一般性行业内容、旧新闻、无明确业务关联的社交活动。

除非有明确证据，不要把访问网站、点赞、员工评论或单个职位直接解释成购买意向。综合多个独立信号后再给出优先级。

### 第五步：形成销售假设

为每个关键假设填写：

| 项目 | 内容 |
|---|---|
| 观察到的事实 | 可引用的事件、职位、页面或声明 |
| 可能的问题 | 对公司流程、成本、风险、增长或收入的影响 |
| 可能的相关角色 | 需要验证的使用者、影响者或买方 |
| 证据强度 | 高 / 中 / 低 |
| 验证问题 | 首次对话中应询问的问题 |
| 推荐动作 | 个性化触达、转介绍、内容发送、会议准备或暂缓 |

推断要使用“可能”“表明”“值得验证”等措辞，避免过度确定。

### 第六步：输出账户简报

默认使用以下结构：

1. **一句话结论**：是否值得优先投入，以及原因。
2. **公司概览**：基本画像、产品、规模、地点和商业背景。
3. **近期变化**：按日期倒序列出重要事件。
4. **联系人画像**：职位、影响力、经历、公开关注点和待确认事项。
5. **购买信号表**：信号、证据、日期、强度、关联和推荐动作。
6. **销售假设**：最值得验证的业务问题、可能价值和风险。
7. **个性化切入点**：不超过三条，引用具体事实，不使用空泛赞美。
8. **建议问题**：按发现问题、影响、优先级、流程和下一步分类。
9. **下一步计划**：建议触达对象、渠道、时机、消息重点和退出条件。
10. **信息缺口与可信度**：列出未确认内容、冲突来源和研究截止日期。
11. **来源**：按重要性列出来源与日期。

如果用户要求外联文案，先完成研究，再把事实转成简短、克制、可验证的个性化内容；不要把未确认推断写入文案。

## 多账户研究与排序

研究多个账户时，将每个账户标准化为同一字段，并采用透明评分而非凭直觉排序。可按以下维度各评一至五分：

- 画像匹配度；
- 问题或用例相关性；
- 近期购买信号；
- 联系人可达性与影响力；
- 进入时机；
- 证据可信度。

总分只能帮助排序，不能代替人工判断。对高分账户说明“为什么现在行动”，对低分账户说明“缺什么证据或为什么暂缓”。

## 资源

- `references/signal-indicators.md`：购买信号分类、强度与解读边界。
- `references/research-checklist.md`：公司、联系人、证据和交付质量检查清单。
- `scripts/company-enricher.py`：从结构化输入汇总公司公开资料，输出统一字段；不会绕过访问限制，也不会凭空补全数据。
- `scripts/linkedin-parser.py`：将用户提供或已合法获取的职业资料整理为结构化字段；不负责抓取登录后的页面。

## 质量检查

交付前检查：

- 是否回答了用户的研究目的，而不是堆砌资料；
- 重要事实是否有来源和日期；
- 是否明确区分事实、推断和建议；
- 是否说明了证据新鲜度与可信度；
- 是否识别至少一个反证或风险；
- 是否给出具体的验证问题和下一步；
- 是否避免敏感个人信息、编造数据和无依据的购买意向；
- 是否完全围绕目标客户、方案和销售阶段。
