# 汽车电子上市公司销售方法论

## 客户价值与项目制胜系统（v1.0）

> **适用对象**：面向主机厂、Tier 1、出行平台及海外客户，销售汽车电子软硬件产品、测试设备、智能座舱/智驾/车联网方案、开发服务和生态服务的上市公司。
>
> **本方法论的核心命题**：汽车电子销售不是“把产品卖出去”，而是帮助客户在一个有明确车型、平台、法规、质量和量产节点约束的项目中，**降低决策风险、缩短开发周期、确保量产结果，并形成可审计的商业回报**。

---

## 一、先废掉旧的销售观：我们不再靠“关系、讲解、跟单”取胜

知识库中已有的内容有价值，但不能直接作为公司级销售体系：

| 现有内容 | 可以保留 | 必须补齐或纠正 |
|---|---|---|
| “信任、安全感、降低风险” | 作为客户心理底层 | 不能停留在抽象的人性描述，必须落到验证计划、质量证据、责任边界和量产承诺 |
| 100个客户问题 | 作为访谈素材库 | 问题过宽、没有阶段顺序，也没有“问完后要得到什么证据”和退出标准 |
| 销售研究清单 | 作为账户研究基础 | 需要增加车型/平台、采购窗口、供应商准入、质量体系、量产节点和竞品格局 |
| Deck、Demo、异议处理模板 | 作为销售工具 | 必须绑定客户角色、项目阶段、决策门和下一步，不再做泛化材料 |
| 商机表、周报、Forecast | 作为管理基础 | 需要从“报进展”升级为“报证据、报风险、报下一步、报资源申请” |

### 新旧方法的根本区别

| 旧式销售 | 新式汽车电子销售 |
|---|---|
| 找人、建立关系、介绍产品 | 找项目、识别问题、建立价值假设 |
| 客户说有需求，就认为有商机 | 只有被预算、车型、时间、决策链和验证动作共同证实，才算商机 |
| 追客户回复 | 推动客户完成一个可验证的项目里程碑 |
| 低价争取入围 | 以总拥有成本、量产风险和交付确定性赢单 |
| 销售单兵作战 | 销售牵引“客户—产品—研发—质量—交付—财务”联合战队 |
| 签合同即结束 | SOP、量产爬坡、回款和二次复制才是订单闭环 |

## 二、销售总纲：一条主线、四个结果、六道门

### 1. 一条主线

> **以客户车型/平台项目为载体，以客户经营指标为价值锚点，以证据链为推进抓手，以量产和回款为最终闭环。**

### 2. 四个结果

每个销售动作都必须同时服务四个结果：

1. **客户结果**：解决一个真实且有优先级的问题，改善成本、周期、体验、质量、合规或收入。
2. **项目结果**：进入客户正式项目流程，拿到明确的验证、定点或采购里程碑。
3. **公司结果**：获得合理毛利、可控交付风险、可复制的客户资产和可回款的合同。
4. **资本市场结果**：形成可解释、可追踪、可审计的收入质量，而非只追求短期订单数字。

### 3. 六道机会门（Opportunity Gates）

商机不以“客户感觉不错”分级，而以证据过门：

| 门 | 目标 | 必须拿到的证据 | 过门标准 |
|---|---|---|---|
| G0 账户选择 | 判断值不值得投入 | 客户战略、产品/车型规划、供应商格局、切入路径 | 有明确的业务假设和责任人 |
| G1 项目确认 | 证明不是泛需求 | 项目名称、车型/平台、应用场景、时间节点、客户项目负责人 | 客户承认问题且愿意共同澄清 |
| G2 价值确认 | 证明客户为什么现在要做 | 痛点基线、目标指标、不做代价、预算来源或预算窗口 | 至少一个量化目标和一个内部推动者 |
| G3 方案验证 | 证明能做且风险可控 | 技术方案、接口/法规/质量要求、样件或Demo、测试计划 | 关键假设被验证，问题清单有负责人和日期 |
| G4 商务定点 | 证明客户愿意承担采购责任 | 采购流程、报价边界、定点规则、合同条款、付款条件 | 进入正式RFQ/定点/合同评审 |
| G5 量产与复制 | 证明订单真正产生价值 | PPAP/验收、SOP、爬坡、回款、质量复盘、复制计划 | 量产交付、回款达成，并形成下一项目入口 |

**管理原则**：没有证据，不升阶段；连续两个周期没有新增证据，商机自动降级或冻结；没有客户共同动作的“下一步”，不算下一步。

## 三、汽车电子客户的五层价值：不要只卖功能

汽车电子项目的价值必须按客户的经营链条表达：

| 价值层 | 客户真正关心的问题 | 销售必须回答的问题 | 可量化指标示例 |
|---|---|---|---|
| 经营层 | 这件事是否支持车型成功、品牌升级或海外增长？ | 不做会损失什么，做成能带来什么？ | 车型竞争力、选装率、海外适配数、收入/毛利 |
| 项目层 | 能否按节点量产？ | 谁在什么时候交付什么结果？ | 开发周期、里程碑达成率、变更次数 |
| 工程层 | 能否集成、验证、维护？ | 接口、算力、数据、工具链和版本如何闭环？ | 集成工时、缺陷率、自动化率、响应时间 |
| 质量/合规层 | 出问题谁负责？ | 如何证明安全、质量、隐私和法规满足要求？ | 一次通过率、缺陷关闭周期、合规覆盖率 |
| 财务层 | 投入产出是否合理？ | TCO、毛利和付款风险是否可接受？ | 单车成本、项目毛利、回收期、现金转换周期 |

### 价值表达公式

> **客户价值 = 增量收益 + 可避免成本 + 可避免风险 − 采用成本 − 切换成本**

销售不能只报“功能清单”和“单价”，必须完成一张**客户价值账**：

```text
客户当前基线 → 目标改善值 → 我方贡献 → 证据来源 → 验证方式 → 价值归属人
```

如果无法写出“基线”和“验证方式”，只能称为价值假设，不能在报价或汇报中写成确定收益。

## 四、账户经营：从“客户名单”升级为“客户作战地图”

### 1. 账户分层

采用“战略价值 × 赢单可能性 × 交付可控性”三维分层，而不是只按客户规模排序：

| 层级 | 判定 | 经营策略 |
|---|---|---|
| S级战略账户 | 对收入、品牌、平台复制或资本市场有重大影响 | 高层共识、联合规划、季度作战、专属资源和风险预案 |
| A级重点账户 | 有明确项目和较高近期转化可能 | 账户计划、项目战队、月度评审、重点突破 |
| B级成长账户 | 有业务匹配，但项目或关系尚未成熟 | 标准化内容培育、事件触达、验证需求 |
| C级观察账户 | 信息不足、价值低或当前无窗口 | 低成本维护，达到信号阈值再投入 |

### 2. 每个重点账户必须有一页作战地图

1. **客户战略**：客户未来12—24个月的产品、平台、区域和技术方向。
2. **项目地图**：车型/平台、SOP、RFQ、样件、定点、量产、改款和复制机会。
3. **组织地图**：业务发起人、使用者、技术评审、质量、采购、财务、法务、最终批准人，以及各自的目标和顾虑。
4. **供应商地图**：现有供应商、竞品、替代方案、自研方案、客户内部偏好和切换阻力。
5. **价值地图**：每个角色要改善的指标、反对理由、需要的证据、我方可调用的资源。
6. **风险地图**：客户预算、项目延期、技术缺口、交付产能、回款、合规、舆情和上市公司披露风险。
7. **切入与扩张路径**：从单点产品到平台/车型，再到客户集团复制的路径。

### 3. 账户触达的“四种关系”

不能把“联系人多”误当作关系深。每个重点账户至少要建立：

- **业务关系**：客户愿意讨论业务目标和优先级。
- **技术关系**：客户愿意共同定义接口、指标和验证方案。
- **采购关系**：清楚供应商准入、价格、合同和定点规则。
- **高层关系**：双方高层对合作边界、战略价值和风险有共识。

关系的有效证明不是微信好友，而是客户是否愿意让我们参与下一次关键决策。

## 五、项目型销售主流程：八步推进法

### 第1步：选战场（Account & Arena）

**目标**：不在错误客户、错误车型、错误窗口上消耗资源。

**必做动作**：

- 明确客户、车型/平台、产品线、区域和预计SOP；
- 判断是新增项目、替换项目、降本项目、改款项目还是海外适配项目；
- 识别现供应商和客户自研边界；
- 给出“为什么现在、为什么我们、为什么这个项目”的三句话假设。

**退出条件**：找不到具体项目、时间窗口和切入人，不进入高强度开发。

### 第2步：做客户发现（Customer Discovery）

客户发现不是问完100个问题，而是围绕五个问题形成证据：

1. 客户要完成什么业务结果？
2. 当前哪里卡住，造成什么代价？
3. 为什么现在必须解决？
4. 谁会推动、谁会反对、谁承担责任？
5. 客户用什么标准判断方案成功？

**推荐访谈顺序**：业务结果 → 项目节点 → 当前方案 → 问题代价 → 决策链 → 技术/质量约束 → 采购规则 → 下一步共同动作。

**拜访纪要只保留四类内容**：客户原话、已确认事实、待验证假设、下一步承诺。泛泛的“客户认可”“关系不错”不得作为结论。

### 第3步：共创价值（Value Co-creation）

组织客户、销售、产品、研发、交付和财务共同完成一页《价值确认表》：

| 项目 | 当前基线 | 客户目标 | 我方贡献 | 证据/数据 | 验证人 |
|---|---|---|---|---|---|
| 周期 |  |  |  |  |  |
| 成本 |  |  |  |  |  |
| 质量 |  |  |  |  |  |
| 体验/功能 |  |  |  |  |  |
| 合规/风险 |  |  |  |  |  |

**原则**：价值由客户确认，不由销售自说自话；价值必须绑定项目指标，不用“领先、先进、赋能”等空泛形容词替代。

### 第4步：设计赢单方案（Win Solution）

方案必须同时回答四层问题：

- **业务方案**：客户为什么要投、能改善什么；
- **技术方案**：系统边界、接口、算力、数据、版本和集成方式；
- **交付方案**：里程碑、资源、测试、变更、质量和服务；
- **商务方案**：License/开发费/服务费/单车费等模式、付款、毛利和风险边界。

每一份方案要标出：已验证、待验证、客户输入、我方承诺、明确不包含。边界越清楚，后续毛利越可守。

### 第5步：建立证据链（Proof）

汽车电子销售不靠“相信我”，而靠分层证据：

1. 公司与资质证据；
2. 产品与架构证据；
3. 样件/Demo/测试证据；
4. 量产与质量证据；
5. 客户案例与第三方证据；
6. 交付、服务、备件和持续运营证据。

**证据分级**：A=客户/第三方可核验；B=公司内部测试或已交付记录；C=产品规划、口头承诺或推断。对外报价、定点和高层汇报优先使用A/B级；C级必须标注“规划/待验证”。

### 第6步：推动客户决策（Decision Orchestration）

销售要管理的是客户的决策过程，不是催促某个联系人。

**必须画出的决策链**：

```text
触发者 → 需求提出者 → 技术评审者 → 使用/交付负责人 → 采购议价者 → 预算批准者 → 合同签署者
```

对每个角色回答：他的目标、担忧、评审材料、可接受承诺、下一步动作是什么？

**客户内部销售包**至少包含：一页业务价值、方案边界图、验证结果、项目计划、风险与兜底、商务摘要、内部汇报话术。

### 第7步：商务与定点（Commercial Close）

报价前必须完成四项检查：

- 需求是否冻结到可报价的程度；
- 变更、验收、售后、质保和责任边界是否写清；
- 成本、毛利、现金流、信用和回款风险是否经过审批；
- 客户的正式采购流程、供应商准入和定点标准是否确认。

**谈价顺序**：先确认价值与范围，再讨论价格；先拆总拥有成本，再拆单价；先谈条件交换，再做无条件让步。

**让步纪律**：每次让步必须换取客户的确定动作，例如锁定车型/数量、缩短付款周期、减少定制、提供测试资源或完成定点时间承诺。

### 第8步：量产交付与扩张（Launch & Expand）

签约后的销售责任不结束，销售必须参加：样件、试装、测试、问题关闭、SOP、爬坡、回款和复盘。

量产后30/60/90天完成：

- 客户结果复盘：价值是否实现；
- 质量复盘：重大问题、重复问题和预防措施；
- 商务复盘：毛利、回款、变更收入和索赔；
- 扩张复盘：同平台、同集团、同区域和下一代车型机会。

## 六、销售与技术、交付、质量的协同机制

### 1. 机会战队（Deal Team）

每个A级以上商机建立战队：

| 角色 | 责任 |
|---|---|
| 机会负责人（销售） | 统一客户策略、证据、节奏、Forecast和资源申请 |
| 方案负责人（产品/架构） | 方案边界、价值假设、技术风险和演示 |
| 验证负责人（研发/测试） | POC、测试、问题关闭和证据归档 |
| 交付/质量负责人 | 量产可行性、质量门、服务和变更边界 |
| 商务/财务/法务 | 报价、毛利、付款、合同和上市公司合规 |
| 高层Sponsor | 高层关系、关键冲突和重大资源协调 |

### 2. 三张会必须分开

- **Pipeline会**：只讨论阶段、证据、风险、下一步和资源；
- **项目交付会**：只讨论里程碑、问题、质量、变更和责任人；
- **经营复盘会**：只讨论收入、毛利、回款、预测准确率、客户健康度和复制。

把三种会议混在一起，会出现“技术很忙、销售很乐观、财务最后才知道风险”的失控状态。

### 3. 红线问题

以下情况必须升级到销售负责人和相关高管，不得由一线销售自行承诺：

- 未经批准的量产时间、性能指标、独家、价格或赔偿承诺；
- 可能影响产品安全、法规、数据合规或公司信息披露的事项；
- 毛利低于底线、付款条件异常或客户信用风险高；
- 需求超出产品边界但尚未完成变更评审；
- 客户要求隐瞒缺陷、绕过认证/测试或以口头承诺代替合同。

## 七、Forecast与商机管理：只预测“有证据的收入”

### 1. 商机字段最低要求

每条商机必须有：

- 客户、项目/车型/平台、产品线、区域；
- 商机来源和触发事件；
- 当前阶段与进入日期；
- 客户问题、基线、目标和不做代价；
- 关键联系人及角色；
- 预算/采购来源、竞争态势和现供应商；
- RFQ、样件、验证、定点、SOP、回款节点；
- 金额、币种、毛利、收入确认假设；
- 已完成证据、待验证假设、客户共同动作；
- 下一步动作、责任人、日期和失败/退出条件；
- 需要公司支持的事项及最晚决策时间。

### 2. Forecast分层

| 层级 | 含义 | 管理口径 |
|---|---|---|
| Commit | 客户和内部均已完成关键承诺，合同/定点和交付路径清晰 | 可纳入承诺预测，但仍需列出风险 |
| Best Case | 关键证据基本具备，仍有一至两个外部变量 | 作为上行情景，不得当成确定收入 |
| Pipeline | 尚在发现、验证或竞争阶段 | 用于资源配置，不进入确定预测 |
| Omitted/No Decision | 信息不足、窗口消失或客户不决策 | 主动剔除，防止虚胖 |

### 3. 健康度评分（100分）

| 维度 | 分值 | 核心问题 |
|---|---:|---|
| 项目与时间 | 20 | 是否有正式项目、车型和明确节点？ |
| 痛点与价值 | 15 | 是否有客户确认的基线、目标和不做代价？ |
| 决策链 | 15 | 是否接触关键角色且知道批准路径？ |
| 技术与质量 | 15 | 关键假设、接口和风险是否已验证？ |
| 竞争与位置 | 10 | 现供应商、竞品和客户自研边界是否清晰？ |
| 商务与预算 | 10 | 预算、采购流程、报价和合同条件是否明确？ |
| 客户共同动作 | 10 | 客户是否安排资源并完成承诺动作？ |
| 交付与回款 | 5 | 产能、交付、信用和回款风险是否可控？ |

**建议阈值**：80分以上可进入重点资源池；60—79分限期补证；60分以下不得包装成重点商机。

## 八、不同客户角色的作战语言

| 客户角色 | 他要避免什么 | 他要证明什么 | 我方材料 |
|---|---|---|---|
| CEO/事业部负责人 | 车型失败、战略落空、供应商失控 | 这笔投入能否形成竞争力和可复制增长 | 一页战略价值、标杆案例、风险兜底 |
| 研发/架构 | 集成困难、版本失控、技术债 | 能否按接口和指标交付 | 架构图、接口清单、测试与问题关闭计划 |
| 项目经理 | 节点延期、跨部门扯皮 | 谁在何时交付什么 | 里程碑、RACI、风险清单、升级机制 |
| 质量/法规 | 事故、召回、审核不通过 | 质量体系、证据和责任闭环 | 测试报告、质量门、合规说明、服务SLA |
| 采购 | 价格失控、供应商不配合 | 条件透明、可比价、可交付 | 商务报价、TCO、付款/质保/变更边界 |
| 财务 | 投入浪费、回款困难、毛利不清 | 现金回收和收益合理 | 价值账、成本结构、付款与信用方案 |
| 一线使用者 | 上手难、工作量增加、出问题没人管 | 方案真的让工作更简单 | Demo、操作流程、培训和服务通道 |

## 九、关键话术：不靠压迫，靠共同验证

### 1. 首次沟通

> “今天不急着介绍全套产品。我想先确认贵司的车型/平台、量产节点和当前卡点。如果问题不成立，我们就不浪费双方时间；如果问题成立，再一起判断是产品、联合开发还是暂时不做。”

### 2. 客户只说“发资料”

> “可以。为了不发一套与项目无关的资料，我只确认三点：对应哪一条产品线/车型？希望重点看成本、周期、功能还是合规？看完资料后，哪位同事一起判断是否进入技术澄清？”

### 3. 客户只比价格

> “如果只比较单价，我们可能不是最合适的供应商。建议先把开发、集成、测试、变更、售后和延期风险放在同一张TCO表里；如果算完仍然只看单价，我们再决定是否参与。”

### 4. 客户说“你们没有量产”

> “量产证据需要按具体产品、车型、客户和交付范围说清楚。我们把已量产、已验证、正在导入和规划中的内容分开列，贵司可以据此判断哪些能力能直接复用，哪些需要先做POC。”

### 5. 客户说“内部再讨论”

> “可以。为了帮您内部讨论得更快，我想确认内部需要回答哪三个问题：价值是否成立、技术是否可行、风险谁来承担？我们可以分别准备一页材料，并约定由哪位负责人在什么时间反馈结论。”

### 6. 项目延期或客户沉默

> “我不把没有回复理解成拒绝，也不把它理解成推进中。请您帮我确认：项目仍在、预算仍在、窗口仍在，还是目前进入No Decision？如果窗口消失，我们会先冻结资源，等新的触发事件出现再重启。”

## 十、销售管理者的周/月/季度机制

### 每周：看证据和阻塞

每个销售只汇报五件事：

1. 本周新增了什么客户事实；
2. 商机过了哪一道门，证据是什么；
3. 哪个关键风险正在扩大；
4. 下周客户要完成什么共同动作；
5. 需要公司哪个角色在什么日期前支持。

### 每月：看经营质量

- 新增商机转化率；
- 阶段停留天数和冻结商机比例；
- RFQ到定点、定点到SOP的转化率；
- Forecast准确率；
- 平均毛利、折扣率、变更收入；
- 回款达成率、逾期率和客户集中度；
- 重大质量问题、索赔和客户健康度。

### 每季度：看战略与复制

- 重点账户收入、毛利和项目覆盖；
- 同平台/同集团/同区域复制数；
- 失单原因Pareto及产品改进闭环；
- 竞争格局和客户自研变化；
- 研发投入与可售产品的匹配度；
- 未来两个季度的量产收入可见性；
- 对外披露、审计、合规和重大合同风险。

## 十一、销售能力认证：销售不是“会说”，而是“能带项目过门”

### L1：基础销售

- 能讲清产品边界和适用场景；
- 能完成账户研究和客户发现；
- 能输出合格拜访纪要和下一步；
- 能识别不应承诺的红线。

### L2：项目销售

- 能独立管理G0—G3商机；
- 能完成价值账、决策链和方案简报；
- 能组织产品、研发、质量和交付战队；
- 能识别假商机并及时退出。

### L3：大客户/行业销售

- 能经营S/A级账户及客户高层；
- 能主导RFQ、定点、合同和关键谈判；
- 能平衡收入、毛利、交付和回款；
- 能将单项目复制成平台、集团和区域增长。

### 认证方式

不以考试背诵为主，采用“真实商机评审 + 客户材料演示 + 复盘答辩”：

- 证据是否真实；
- 价值是否客户确认；
- 决策链是否完整；
- 技术和交付风险是否可控；
- 下一步是否有客户共同动作；
- Forecast是否与事实一致。

## 十二、立即落地：30/60/90天推进计划

### 0—30天：统一语言和数据

- 清理现有商机，按G0—G5重新定级；
- 为Top 20账户建立作战地图；
- 统一商机字段、Forecast口径和退出条件；
- 建立产品证据库：已量产/已验证/规划中分层；
- 选3个真实商机试跑价值账和机会战队。

### 31—60天：跑通项目制销售

- 对Top商机完成客户决策链和技术/质量风险评审；
- 形成按角色定制的客户内部销售包；
- 用真实RFQ或POC开展报价与让步训练；
- 建立失单、延期、低毛利和重大质量问题复盘机制；
- 将周会从“汇报进展”改为“过门评审”。

### 61—90天：把方法变成组织能力

- 复盘首批商机的阶段转化率和Forecast准确率；
- 固化标准模板：账户地图、发现纪要、价值账、证据清单、决策链、报价审批、量产复盘；
- 建立销售能力认证和新人训练营；
- 将客户声音进入产品规划、质量改进和资源预算；
- 形成季度级重点账户经营会和收入质量报告。

## 十四、最终判断标准

一套销售方法论是否有效，不看文档写得多漂亮，而看六个问题：

1. 销售能否在10分钟内说明这个商机为什么存在？
2. 客户能否说出不解决问题的代价？
3. 技术、质量、交付、财务是否在同一张风险图上？
4. 每个阶段是否都有可核验的证据和客户共同动作？
5. 报价是否保护毛利、现金流和上市公司合规边界？
6. 项目量产后，是否产生回款、案例和下一项目复制？

如果六个问题不能回答，销售团队不是“还需要继续跟进”，而是需要回到客户发现或退出这个商机。

> **销售管理者的最后一句话**：我们不奖励“最会讲的人”，我们奖励“能把客户项目从问题带到量产，并且让公司赚到合理利润的人”。
